# UI/UX review and improvement plan

Reviewed 2026-09-29 using the ui-ux-pro-max web accessibility, interaction, layout, navigation, and chart guidance, with Ponytail simplicity constraints.

**Recommendation:** retain MkDocs Material, Plotly, Inter, and the existing teal identity. Prioritize correct and understandable results, accessible controls, and useful defaults before visual polish. The current stack can support these improvements without a framework migration or new UI dependency.

**Scope and evidence:** reviewed the site configuration, Markdown pages, both dashboard scripts, custom CSS, countdown, dashboard-data generator, scoring code, and checked-in JSON. `mkdocs build --site-dir /tmp/macro-hub-ux-review-site` passed. Browser inspection stalled before the local pages could be examined. Findings below are source/data findings; viewport behavior, computed contrast, screen-reader behavior, and runtime performance remain unverified. This is a UI/UX review, not a complete statistical or backend audit.

**What already works**

- Material supplies a consistent documentation shell, search, navigation, and theme switching.
- Most filters use native, visibly labeled inputs; controls and model selections already wrap.
- Time-series line charts suit the product. Prediction bands, explicit transformations, zoom reset, and an origin slider are useful foundations.
- Forecast data is split by target, evaluation scores have a cache, and model colors stay stable within each loaded target.

**Prioritized findings**

| Priority | Finding and evidence | Improvement |
|---|---|---|
| P1 | **The ensemble point forecast disappears.** `docs/js/forecasts.js:445` selects `entry.mean || entry.q050`. The generator emits a mean array even when all entries are null. Checked-in CPI ensemble data has null means and valid medians, so the array prevents fallback. The tooltip always says “Mean.” | Fall back to the median for missing mean values and label the displayed statistic accurately. Verify with the existing ensemble data. |
| P1 | **Leaderboard ranks disagree with the documented method.** `docs/js/evaluation.js:442` assigns sequential ranks, breaking ties by model order, after averaging horizons. `src/scoring/score_forecasts.py:152` ranks individual cells using minimum ranks for ties. TVNN and TVNN-EW have identical checked-in CPI MAE arrays but the browser assigns different ranks. | Use the documented per-cell aggregation and tie policy consistently. Show the number of scored cells and coverage so unequal samples are visible. |
| P1 | **Some summary signals are misleading.** `docs/js/evaluation.js:460` averages absolute scores across log-change targets and unemployment percentage-point changes. At line 541, a fixed tolerance of 0.001 highlights non-winning scores as “best”; that tolerance is large relative to inflation errors. | Keep Overall for ranks; omit Overall for absolute scores. Use a deliberate tie rule consistent with scoring and an explicit “Best” label. Keep numeric values sortable and use tabular figures. |
| P1 | **Custom controls block keyboard access.** `docs/evaluation/leaderboard.md:8` uses click-only div tabs. `docs/forecasts/latest.md:85` has an unnamed range input. The document-wide Space handler at `docs/js/forecasts.js:213` intercepts normal button activation. | Use button-based tabs with selected state, panel relationships, and keyboard behavior. Label the origin slider and expose its date through `aria-valuetext`. Scope shortcuts to the explorer and avoid consuming keys on other controls. Add explicit play/pause names and visible focus styling. |
| P1 | **Loading failures can look like missing data or leave stale results.** Forecast requests at `docs/js/forecasts.js:228` mutate shared state without guarding overlapping target changes. Fetch failures become “No forecast data,” while the initial truth request has no user-facing catch. Evaluation similarly swallows failures at `docs/js/evaluation.js:125`; its missing-data branch clears only the main chart. | Keep only the latest request's result, distinguish loading/error/empty states, offer Retry, announce status, and clear or mark every dependent panel consistently. Validate From ≤ To and disable origin controls when no origins exist. |
| P2 | **The landing state does not match the navigation promise.** `docs/js/forecasts.js:36` starts at index zero: January 2000 in all four current files. `docs/js/evaluation.js:119` opens Scores, hiding the rankings behind Summary; summary rows are alphabetic at line 501. | Open Latest Forecasts at the latest available origin with a useful recent window. Keep full history available. Open Leaderboard on the rank table, sorted by Overall rank, with score history as the secondary view. |
| P2 | **Forecast values are hard to interpret precisely.** `docs/js/forecasts.js:450` formats means to two decimals: an existing value of 0.0022 displays as 0.00. Bands suppress hover information and legend entries. Chart data has no equivalent accessible table. | Use precision appropriate to transformed units, name the statistic and units, explain 80%/90% bands beside the plot, and offer a table of the selected forecast with CSV download. Add a concise text description and distinguish model lines by dash/marker as well as color. |
| P2 | **Freshness and participation information conflict.** The homepage says “Live Arena,” but checked-in forecasts end on 2026-04-15. `README.md` and `docs/participate/how-to-submit.md` require PAYEMS, while `hub-config/tasks.json` and `docs/participate/format.md` make it optional. Public horizon examples and zero-based dashboard data also need reconciliation. | Show latest origin, truth coverage, and generation time from data. Identify historical backfills separately from prospective submissions. Align participation text with the implemented contract; clearly distinguish stored horizon values from user-facing labels. Show the next registration date and Eastern timezone beside the countdown. |
| P2 | **Small-screen layout needs a dedicated pass.** `docs/css/dashboard.css:93` keeps three buttons, the slider, and a minimum-width date on one unwrapped row. The custom summary table has no dedicated overflow wrapper; plot margins, titles, and heights are fixed. | Put date and playback controls on a separate row at narrow widths; give the slider a full row. Contain table scrolling within a labeled region. Adjust chart margins, ticks, and legend placement to width. Confirm behavior at 375, 768, and 1440 CSS pixels and at 200% zoom. These are source-level risks, not measured overflow failures. |
| P2 | **Sharing loses analysis context.** `docs/js/forecasts.js:176` stores only the target. Evaluation stores no filter state. Changing target resets model selections. | Serialize target, origin, models, date range, metric, horizon, and evaluation view in URL parameters, validating restored values. Preserve compatible model selections and define predictable Back behavior. |
| P3 | **Unnecessary work can slow interaction.** `mkdocs.yml:90` loads Plotly and MathJax on every page. Forecast and score fetches are sequential and forecast targets are not cached. Each forecast JSON is about 2 MiB before transfer compression. Evaluation initializes the hidden summary and loads its targets sequentially. `docs/js/evaluation.js:269` adds another relayout listener on every draw. | Load heavy scripts only on relevant pages; initialize the summary when needed; parallelize independent requests and reuse cached data. Bind the relayout listener once or remove the old one as the forecast script already does. Measure before adding workers, virtualization, or a new data architecture. |
| P3 | **Custom styling needs accessibility and consistency checks.** Both stylesheets use some hardcoded colors. The live pulse and spinner have no reduced-motion alternative. Both chart scripts repeat the same palette. | Reuse Material semantic variables, add a small shared set of dashboard colors, verify both themes, provide reduced-motion styles, and standardize focus and control spacing. Preserve a visible textual loading indicator when disabling spinner motion. |

**Proposed page structure**

- **Home:** short purpose statement → latest data/submission status → primary “Explore forecasts” action → secondary leaderboard and participation links → concise indicator coverage → background information.
- **Forecasts:** full indicator name plus code → origin and freshness → target/model/date controls → forecast chart and interval explanation → selected-data table/download → optional accuracy charts → collapsed technical explanation. Keep units visible next to the plot.
- **Leaderboard:** ranked table first → metric, horizon, period, and coverage context → score-history view → methodology link. Put metric definitions near controls rather than requiring a scroll past multiple charts.
- **Participate:** deadline and prerequisites → one valid minimal CSV example plus metadata example → local validation → pull request instructions → troubleshooting. Reuse existing repository templates and validation scripts.

Phases 1 and 2 are the first release. Phase 3 improves the main research workflows. Phase 4 should follow measurement, except the accumulating listener fix, which can accompany any evaluation-script change. Each behavioral fix should leave a small runnable regression check; avoid introducing a broad test framework solely for this work.

**Validation still required**

**Guidance applied**

The local skill searches returned relevant web guidance for keyboard controls and time-series charts. MkDocs/vanilla JavaScript is not one of the skill's listed stacks, so no unrelated React/Tailwind stack rules were applied. Recommended tab behavior follows [WAI's tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/). Chart descriptions and equivalent data follow [WAI guidance for complex images](https://www.w3.org/WAI/tutorials/images/complex/). Native-app-only safe-area, haptic, and bottom-navigation rules were excluded.

Implementation update: the code changes for all four phases are now applied. The existing stack is retained.
